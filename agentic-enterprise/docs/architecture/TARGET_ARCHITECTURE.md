# البنية المستهدفة

**المبدأ (ADR-010):** تطوير النواة الحالية تدريجيًا، لا إعادة بنائها. كل قسم يذكر ما هو **منفّذ** وما هو **مخطط**، ولماذا وبأي شرط ينتقل من مخطط إلى منفّذ.

## 1. الطبقات

```
                ┌───────────────────────────────────────────────────────┐
 واجهات         │ CLI (منفّذ) │ Control API (مخطط) │ Web Console (مخطط)│
                └──────────────────────────┬────────────────────────────┘
                                           │ هوية: توقيع Ed25519 (منفّذ) → SSO/WebAuthn (مخطط)
                ┌──────────────────────────▼────────────────────────────┐
 تنسيق          │ Orchestrator: claim ذري، وleases، وbackoff، وإحالات،     │
                │ وoutcomeGuard (منفّذ) │ DAG workflows وأولويات (مخطط)   │
                └──────────────────────────┬────────────────────────────┘
                ┌──────────────────────────▼────────────────────────────┐
 سياسة وإنفاذ   │ ToolExecutor + Guardrails + Approval Gate (منفّذ)      │
                │ Policy Engine مركزي بإصدارات + ABAC + مستويات الاستقلالية (مخطط) │
                └───────┬───────────────────────────────┬───────────────┘
                ┌───────▼──────────┐          ┌─────────▼──────────────┐
 تشغيل الوكلاء  │ Scripted (منفّذ)  │          │ Model Router (مخطط)     │
                │ Claude Agent SDK  │          │ مزوّدون متعددون بسياسة   │
                │ (منفّذ، غير مقيس) │          │ حساسية البيانات          │

 تكامل          │ Connectors: mocks (منفّذ) │ ERP/بنك/بريد/n8n/MCP (مخطط) │

 بيانات وسجل    │ SQLite WAL (منفّذ) → PostgreSQL (مخطط)                  │
```

## 2. سجل الوكلاء ودورة الحياة (مخطط، P1)

**الحالي:** `AgentDefinition` ثابت في الكود، يُسجَّل عند الإقلاع، بلا إصدار ولا حالة.

**المستهدف:**
- تعريف مُصدَّر يُتحقق منه ويُخزَّن hash له في audit عند كل نشر.
- حقول التعريف: `version`، و`autonomyLevel`، و`budgets` (tokens وتكلفة لكل مهمة ويوم)، و`dataAccess` (namespaces والمجالات)، و`evalRequirement` (أدنى نسبة نجاح evals قبل النشر)، و`status`.
- دورة الحياة: `CREATED → CONFIGURED → VALIDATED → DEPLOYED → ACTIVE ⇄ PAUSED → STOPPED → ARCHIVED`، مع انتقالات صريحة.
- **الإيقاف المؤقت لوكيل بعينه** (PAUSED): المهام في الطابور تبقى، والمطالبة بمهام الوكيل تتوقف، واستدعاءات أدواته تُرفض. إيقاف جراحي بدل الإيقاف الشامل.

**مستويات الاستقلالية:**

| المستوى | المسموح | الإنفاذ في المنفّذ |
|---------|---------|--------------------|
| 0 | مراقبة وتقرير | أدوات read فقط |
| 1 | تحليل وتوصية | read مع escalate |
| 2 | مهام منخفضة المخاطر | مع write |
| 3 | سير عمل محدود بموافقات | مع طلبات approval (الوضع الحالي لكل الوكلاء) |
| 4 | سير عمل ممتد بميزانيات | 3 مع حد أعلى لاستدعاءات الأدوات والإحالات، **ولا يتجاوز أبدًا الموافقات أو الإيقاف** |

**التفويض (delegation):** الإحالة لا توسّع الصلاحيات. المهمة الفرعية تُنفَّذ بصلاحيات الوكيل المستلم، وترث `originator` (منفّذ). المخطط: حد عمق لسلاسل الإحالة (`maxDelegationDepth`) يُفرض في `spawn`.

## 3. محرك السياسات (مخطط، P1/P2)

**الحالي:** السياسة موزعة على ثلاثة أماكن: `defaultPolicy` في البوابة، و`*/shared/policy.ts` لكل مجال، والحواجز.

**المستهدف:** واجهة `PolicyEngine.evaluate(subject, action, resource, context) → {allow|deny|require_approval, reasons, policyVersion}`، ويُسجَّل `policyVersion` مع كل قرار. التنفيذ داخلي بقواعد TypeScript مُصدَّرة، **لا محرك خارجي** حتى تظهر حاجة قياسية إلى مؤلفي سياسات من خارج الفريق.

## 4. سير العمل (مخطط، P1)

**الحالي:** إحالات متسلسلة أو مؤجلة، مع idempotency بالمدخلات.

**المستهدف:** `workflow_runs` بـ DAG بسيط (اعتماديات، وتفرع متوازٍ، وشرطي) فوق جدول المهام نفسه. لا محرك durable خارجي (مثل Temporal) قبل أن يبرره الحجم. الضمانات الحالية (claim ذري، وleases، وdedupe) هي أساسه.

## 5. تعدد المزوّدين وتوجيه النماذج (مخطط، P2)

- واجهة `AgentRuntime` موجودة: الحتمي وClaude. المزوّد الجديد = تنفيذ جديد لها.
- **قاعدة غير قابلة للتفاوض:** التوجيه يمر بسياسة حساسية البيانات. مهمة مصنفة "بيانات شخصية لعميل سعودي" لا تُرسل إلا لمزوّد معتمد لتلك الفئة (`SAUDI_APPLICABILITY.md` §3). لا إعادة توجيه صامتة عند الفشل إلى مزوّد غير معتمد.
- **مطلوب لكل مزوّد:** تطبيع الأخطاء، وتسجيل إصدار النموذج مع كل تشغيل، والتحقق من المخرج المنظم (منفّذ عبر `outputSchema`)، ومحاسبة التكلفة.

## 6. التكاملات وn8n (n8n منفّذ، ADR-015)

- كل تكامل = connector خلف `ToolExecutor`، بصلاحية معلنة (read أو write أو approval)، وschema، ومهلة، وحد معدل، وسجل audit.
- **n8n تحديدًا:** يُستدعى كـ connector يطلق workflow محددًا مسبقًا بمعرّف ثابت (allowlist)، عبر webhook موقّع، ولا يحمل مفاتيح خارجية.
- الإجراءات ذات الأثر داخل n8n تُصنَّف approval في الطرف المستدعي، **فلا يتحول n8n إلى طريق التفاف حول البوابة.**
- **MCP:** خوادم MCP الخارجية تُعامل كأدوات غير موثوقة. مخرجاتها تُغلَّف كمحتوى خارجي.

## 7. تعدد المستأجرين (منفّذ بعزل فيزيائي، ADR-014)

- **المنفّذ:** قاعدة أو schema لكل مستأجر بدل `tenant_id` في كل جدول. السبب في ADR-014.
- مفاتيح تثبيت audit، ومفاتيح الموافقين، وسياسات الاحتفاظ، وموقع المعالجة: **لكل مستأجر**.
- **مخطط:** موقع معالجة لكل مستأجر (قاعدة في منطقة محددة) وسياسات احتفاظ لكل مستأجر.

## 8. القاعدة (PostgreSQL منفّذ، ADR-013)

**الانتقال إلى PostgreSQL مشروط بأحد:**
- أكثر من عامل على أكثر من خادم،
- أو تعدد المستأجرين،
- أو حجم audit يجعل التحقق الكامل أبطأ من 5 ثوانٍ.

الواجهات الحالية (`transaction`، والمستودعات) تنتقل كما هي. `SELECT … FOR UPDATE SKIP LOCKED` يحل محل المطالبة الذرية الحالية.

## 9. واجهة التحكم (منفّذة: `/console`)

الواجهة مستهلك للـ API، لا مسار ثانٍ للصلاحيات. ملف HTML واحد بلا إطار عمل. التوقيع داخل المتصفح بـ WebCrypto Ed25519. **مخطط:** WebAuthn بدل ملف PEM.
